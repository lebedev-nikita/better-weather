# Работа над Better Weather

Нативное Android-приложение на Kotlin. Требования продукта находятся в `PRODUCT.md`; команды сборки, условия API и выпуск APK — в `README.md`.

## Изменения

- Сохраняйте разделение: `data` отвечает за API, модели и кэш; `ui` — за Compose и состояние экрана; `location` — за однократную геолокацию; `widget` — за RemoteViews и фоновые обновления.
- Выполняйте сетевые запросы вне главного потока. Пробрасывайте `CancellationException`, чтобы отмена не превращалась в сетевую ошибку.
- Сохраняйте выбранное место и прогноз одним атомарным снимком. Фоновое обновление виджета должно использовать последнее выбранное место, а не перезаписывать новый выбор старым запросом.
- Определяйте текущий день и час в часовом поясе прогноза. Текущий UV берите из почасового значения, а отсутствующие показания отображайте как «—».
- Геолокация запускается по действию пользователя; поиск города остаётся доступным без разрешения. Координаты для виджета берите из сохранённого места.
- Перед изменениями интерфейса прочитайте `DESIGN.md`. Сохраняйте Material 3, системные отступы, светлую/тёмную темы и масштабирование шрифта. Проверяйте нативный экран в Android-эмуляторе или на устройстве.
- При изменении поставщика данных сверяйте его актуальные условия и сохраняйте атрибуцию. Для Open-Meteo бесплатный endpoint рассчитан на некоммерческое использование.

## Проверка

Для изменений кода:

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Держите тесты небольшими: проверяйте существенную логику и исправленные ошибки. Для правок только документации достаточно проверить ссылки и `git diff --check`. Проверки интерфейса описаны в `docs/VALIDATION.md`; отличайте прежние результаты от проверок текущего изменения.

## Выпуск

- Версия приложения задаётся в `app/build.gradle.kts`: обновляйте `versionName`, а для следующего выпуска увеличивайте `versionCode`.
- Порядок подписанной сборки и переменная `BETTER_WEATHER_SIGNING_PROPERTIES` описаны в `README.md`. Храните ключи и пароли вне Git; сохраняйте тот же release-ключ для последующих выпусков.
- При запросе релиза собирайте и проверяйте APK, публикуйте тег `v<version>` на нужном коммите и прикладывайте APK с SHA-256. Бинарные артефакты находятся в `dist/` и распространяются через GitHub Releases.
- Коммит, push и публикацию выполняйте в пределах инструкции пользователя; завершайте работу после проверки состояния удалённой ветки, тега и приложенных файлов.
